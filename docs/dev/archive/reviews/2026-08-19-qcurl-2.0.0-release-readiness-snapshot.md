## Current release blockers

The evidence column below is the original 2026-08-19 snapshot, not a live status
board. Preserve its date and limitations; evaluate the closure conditions against
the actual candidate rather than treating these old observations as current proof.

As of 2026-08-19, QCurl 2.0 remains
`REMEDIATION_REQUIRED / NOT_READY_FOR_RELEASE`. The blockers are split between
local candidate qualification and publication delivery so that packaging or tagging cannot be
mistaken for proof that the candidate passed the release gate.

### Local candidate qualification

| ID | blocker | current evidence | closure condition |
| --- | --- | --- | --- |
| `L1` | Candidate identity | The current remediation worktree contains tracked modifications and the untracked `docs/roadmap/` tree. It is not a clean `C1`. The `Qt6_CPP17_Coding_Style` and `curl` submodules are clean, but that does not make the superproject a candidate. | Create an authorized `C1` from the completed remediation, then prove that the superproject and both submodules are clean and that the recorded source identity is `C1`. |
| `L2` | Final qualification | The existing `build-release-shared/release/qa-manifest.json` records `stage=remediation`, no ABI mode, only two required package-contract gates, and zero artifacts. The six-tree full check has only been exercised as a dry run for the current tree. | On the clean `C1`, execute the six-tree gate with `--tier full --stage final --abi-mode none`. Every required gate must pass in that fresh run. |
| `L3` | Final evidence integrity | No valid final manifest currently binds the same clean `C1` to the complete source, package, runtime, sanitizer, capability, dynamic-symbol, and documentation artifacts. Focused tests, ordinary pytest/CTest runs, dry runs, and historical PASS records do not establish this binding. | Verify the fresh final manifest against `C1`; reject identity, command, producer-tree, capability, authority, or artifact digest drift; require every registered final gate and artifact to be present and passing. |

### Publication delivery

| ID | blocker | current evidence | closure condition |
| --- | --- | --- | --- |
| `P1` | Release publication | `CHANGELOG.md` is still at `Unreleased`. The `v2.0.0` tag, immutable release packages, checksums, frozen release notes, and GitHub Release have not been created or accepted. | Only after the local manifest reports `READY_FOR_RELEASE`, freeze the notes, build and verify the release packages and checksums, create the tag, publish the GitHub Release, and verify the uploaded assets against the local digests. |

The following are explicitly **not** QCurl 2.0 release blockers:

- a v2 ABI baseline or `qcurl-core-v2.abi.xml`;
- an ABI compatibility diff;
- ABI baseline promotion; and
- CI/CL execution, which is excluded from this local release-readiness decision.

Passing `L1` through `L3` changes only the local candidate verdict. It does not implicitly close
`P1`, authorize Git operations, or publish the release.

The four-component extraction and its focused package/consumer tests are remediation evidence only.
They do not make the dirty worktree a clean `C1`, replace the six-tree final run, or create the
fresh final manifest required by `L1` through `L3`.
