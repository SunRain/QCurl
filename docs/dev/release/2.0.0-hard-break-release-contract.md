# QCurl 2.0.0 hard-break release contract

## Release identity

- Latest published release: `v1.0.0`.
- Current development candidate: `v2.0.0`.
- This document defines the local release-candidate contract. It does not create a tag, push a ref, or publish an asset.
- `PROJECT_VERSION` is `2.0.0`; the `QCurl` and `QCurlOtherExtras` shared libraries use `VERSION 2.0.0` and `SOVERSION 2`.
- The Core shared artifact is `libQCurl.so.2.0.0`.
- `SOVERSION 2` identifies the current loader namespace. It does not promise binary compatibility between QCurl 2.x builds.

The release identity has one ordered route:

1. `R=0d1e57dcd68edcca9c7dcac28841571a8a6e00ad` is the read-only review baseline.
2. `remediation` is the uncommitted implementation and pre-commit verification stage. It is not a release candidate.
3. `C1` is the clean implementation and sole final candidate.
4. `final` runs fresh qualification against clean `C1`; no evidence from `R` or remediation can replace it.

Until this route reaches a passing `final` manifest bound to `C1`, the release state is
`REMEDIATION_REQUIRED / NOT_READY_FOR_RELEASE`.

## Delivery component model

The release ships four logical delivery components backed by three physical libraries, with no fifth module layer:

| component | exported target | artifact | default consumer | role |
| --- | --- | --- | --- | --- |
| Core | `QCurl::QCurl` | shared/static runtime library | yes | asynchronous production network Core |
| Blocking Extras | `QCurl::BlockingExtras` | interface consumer surface; implementation embedded in Core | no | synchronous value-result execution model with explicit package opt-in |
| Other Extras | `QCurl::OtherExtras` | shared/static runtime library | no | Diagnostics, Middleware Extras, and conditional WebSocket aggregation |
| Test Support | `QCurl::TestSupport` | development static library | no | mock/capture support for downstream tests; not production Runtime |

“Default consumer” only describes `find_package(QCurl CONFIG REQUIRED)` without requested
components: it loads `QCurl::QCurl` only. An unfiltered `cmake --install` has different semantics
and installs every component built by the producer tree. Component-filtered packaging may install
only Core or a selected opt-in component family.

The physical artifacts are `libQCurl` (Core plus Blocking Extras implementation),
`libQCurlOtherExtras`, and static `libQCurlTestSupport`. `QCurl::BlockingExtras` remains a separate
exported `INTERFACE` target and `COMPONENTS BlockingExtras` boundary, but there is no independent
`libQCurlBlockingExtras` library, runtime install component, or ABI boundary.

`Preview` is a maturity attribute and `Internal` is a visibility attribute. They are recorded
orthogonally in `tests/public_api/surface_manifest.json`; neither creates a target, install
component family, or compatibility layer. Diagnostics and WebSocket are currently Preview inside
Other Extras, while Middleware Extras is Stable inside the same component.

## Producer tree topology

`full` release evidence uses six physically distinct build trees. Every gate step receives
the producer path through one of these explicit options; no step may substitute another tree:

| tree ID | CLI option | fixed capability | producer responsibility |
| --- | --- | --- | --- |
| `release-shared` | `--release-shared-build-dir` | `BUILD_TESTING=OFF`, `QCURL_BUILD_SHARED_LIBS=ON` | shared install/export/consumer/lifecycle and dynamic-symbol hygiene |
| `release-static` | `--release-static-build-dir` | `BUILD_TESTING=OFF`, `QCURL_BUILD_SHARED_LIBS=OFF` | static install/export/consumer/lifecycle |
| `test-shared-gcc` | `--test-shared-gcc-build-dir` | `BUILD_TESTING=ON`, GCC | GCC QtTest, public API and libcurl consistency |
| `test-shared-clang` | `--test-shared-clang-build-dir` | `BUILD_TESTING=ON`, Clang | Clang QtTest and public API cross-check |
| `asan-ubsan-lsan` | `--asan-ubsan-lsan-build-dir` | `BUILD_TESTING=ON`, Clang, ASan/UBSan/LSan | sanitizer evidence |
| `tsan` | `--tsan-build-dir` | `BUILD_TESTING=ON`, Clang, TSan | thread-sanitizer evidence |

The gate rechecks each tree's resolved path, compiler family, `BUILD_TESTING`,
`QCURL_BUILD_SHARED_LIBS` and sanitizer capability before running a step. Missing paths,
duplicate physical paths or capability drift fail closed. The OFF trees do not register CTest;
`scripts/release_package_evidence.py` builds, installs and runs the four installed-package
consumers and lifecycle report directly from the corresponding OFF tree.

## Hard-break boundary

The v1 to v2 transition may remove public APIs and ABI symbols registered in this contract. It does not relax memory safety, thread ownership, protocol semantics, error propagation, local-fixture requirements, or release evidence.

The registered compatibility removals are:

| removed public API | replacement and caller obligation |
| --- | --- |
| `QCurl::QCNetworkMultipartBody::device() const noexcept` | Use `takeDevice(QObject *parent)` or `takeDevice(QObject *parent, QString *error)`. This transfers ownership rather than querying a device; call it on the source device's owner thread and respect the returned wrapper's parent/lifetime contract. The removed v1 symbol is `_ZNK5QCurl22QCNetworkMultipartBody6deviceEv`. |
| `QCurl::QCBlockingNetworkResult::rawHeaderList() const` | Use `headers()`, which preserves the same ordered key/value result and duplicate headers. |

`QCNetworkRequest::rawHeaderList()` returns header names and remains supported; it is not the
removed blocking-result alias. `QCNetworkReply` raw-header observation remains supported too.
Only its private `QCNetworkReplyTransferState::headerMap` compatibility index is removed;
Retry-After parsing consumes `finalHeaderList`, while the public-query `finalHeaderMap` remains.

The cache policy contract has one route: ordered `QList<QCurl::RawHeaderPair>` input. The three lossy `QMap<QByteArray, QByteArray>` policy overloads and their conversion helper are absent. Header observation and storage APIs remain separate from policy evaluation.

`QCWebSocketPool` remains owner-thread-only, asynchronous, mutex-free, and free of nested event loops. Its four public signals must support synchronous direct-slot reentry for `acquire`, `release`, and `clearPool`. Keepalive evidence covers matching Pong, delayed Pong, wrong nonce, no Pong, and disconnect-after-Ping using the local evidence server.

The acquire result and synchronous lease operations have one pure-value contract:

```cpp
using LeaseId = QCWebSocketAcquireResult::LeaseId;
[[nodiscard]] LeaseResult resolveLease(LeaseId leaseId, QCWebSocket **socket) const;
[[nodiscard]] LeaseResult release(LeaseId leaseId);
[[nodiscard]] bool clearPool(const QUrl &url = QUrl(), QString *error = nullptr);
[[nodiscard]] bool setConfig(const QCWebSocketPoolConfig &config, QString *error = nullptr);
```

`QCWebSocketAcquireResult` carries only status, diagnostics, and an opaque nonzero lease ID. It
does not carry a socket pointer. `resolveLease()` and `release()` must be called on the pool owner
thread while the pool is not `Destroying`; they report wrong-thread, destroyed-pool, invalid,
unknown, and inactive-lease failures through `LeaseResult` without changing pool state. A resolved
socket is a non-owning borrow valid only while the same lease remains active. `clearPool()` and
`setConfig()` return `false` with a stable diagnostic and no state change for rejected calls;
successful calls return `true` and clear the optional error output. No queued or cross-thread
mutator route is provided. `preWarm()` reports a failed synchronous lease release as one
`ConnectionFailed` result and does not increase the warmed count.

Static testing is unsupported. `QCURL_BUILD_SHARED_LIBS=OFF` together with `BUILD_TESTING=ON`
must fail during configure with the fixed diagnostic
`QCURL_STATIC_TESTING_UNSUPPORTED：静态构建不支持测试`; only the negative configure test
covers that rejected combination.

## Release evidence

QCurl 2.0 uses a **source-compatible, rebuild-required, non-stable ABI contract**:

- The documented Core component install surface is the 2.x source compatibility boundary. Source-breaking Core changes require a new major release.
- Downstream projects must rebuild and relink against every QCurl update. A binary built against one QCurl 2.x build must not be assumed to work with another.
- The contract does not cover private/internal headers or the three non-Core components unless their own component documentation says otherwise. A Preview marker is maturity metadata, not a component boundary.
- No `qcurl-core-v2.abi.xml` baseline is established or required for 2.0. A missing v2 baseline is not a release blocker.
- The default full/final gate uses `--abi-mode none` and produces no ABI compatibility report or snapshot.
- The Core dynamic-symbol allowlist covers both Core and embedded Blocking Extras public symbols. Other Extras retains its independent allowlist. These checks reject unintended implementation exports but do not prove binary compatibility. Test Support is static-only and therefore has no shared-library symbol allowlist.

### Package-internal component bridges

Two non-installed bridge groups are intentionally exported from Core so separately compiled
components from the same QCurl package can link without exposing private owner types:

- Other Extras: `registerPersistentTransfer` and `removePersistentTransfer`.
- Test Support: `installNetworkMockProvider`.

Their declarations remain in `_p.h` headers and are absent from every install manifest. They are
lockstep implementation contracts between artifacts built from the same QCurl source identity, not
public source APIs or a stable ABI promise. `scripts/qcurl_abi_symbols.py` owns the exact bridge
owner allowlist; adding another owner requires an explicit contract and regression-test update.
Blocking helpers are now internal symbols within Core and require no cross-library bridge export.

### Version-controlled authority and CI inputs

The sole release identity authority is this file:
`docs/dev/release/2.0.0-hard-break-release-contract.md`. Full release runs must provide exactly
`--authority docs/dev/release/2.0.0-hard-break-release-contract.md`; missing, duplicate or additional
authority inputs are rejected. UCE uses the same file by default. Missing required authority
must fail, not become an empty digest or a successful snapshot.

The policy-code dictionary is maintained in `docs/dev/uce/policy_violations_dictionary.json` and
`docs/dev/uce/policy_violations_dictionary.md`. Both are version-controlled CI inputs; the validator
requires matching code sets and rejects missing files or unregistered codes. Their contents,
like other source and test inputs, participate in the candidate's tracked/untracked identity.

`.helloagents/` is an entirely ignored local workspace. Plans, task progress, session state,
finding maps and QA/closeout output stored there are not release authority or CI inputs.
Their absence or local edits must not prevent a normal checkout from running these gates or
change its candidate identity. Durable decisions belong in the version-controlled contract,
not in a timestamped local plan. The former `--contract-json` local-plan option is removed.

Historical review documents are not authority inputs either, but version-controlled reviews
still participate in source identity. This contract supersedes local plans' unfinished ABI
promotion and baseline stages; those stages are not QCurl 2.0 release requirements.

### UCE acceptance and retirement evidence

The complete `basic-no-problem` acceptance workflow is replaced only by equivalent-or-stronger
UCE nightly evidence on the final deletion candidate, without a wrapper, alias, fallback or
parallel acceptance tier. The minimum contract is:

- Preserve push on `master`, `main` and `develop`, manual dispatch, applicable source/document
  path filters, recursive checkout, dependency installation, configure/build and infrastructure tests.
- Execute public-api-slow, capability QtTest with `skip=fail`, strict offline/env tests with a
  local httpbin fixture, and libcurl consistency p0. Additional p1/p2 or specialized contracts
  do not replace any of these checks. Empty selections, listing failures and nonzero commands fail.
- Record workload/finalization exceptions as `gate_exception` and archive failures as their
  registered policy codes; return failure while retaining available diagnostic evidence.
- Bind each former fail-closed branch to an executable negative assertion in the existing
  infrastructure tests. A source reference or manually completed coverage table is not proof.
- Require `<run-id>/manifest.json`, `<run-id>/policy_violations.json`, `<run-id>.tar.gz` and
  `<run-id>.archive-envelope.json`. Independently verify every file, internal/external metadata
  equality, archive member integrity, complete gzip data and the envelope digest/size. Failed
  archives are diagnostic evidence, never accepted success. CI still uploads available diagnostics.
- Freeze source and version-controlled contracts before final evidence. Require at least one
  complete fresh nightly with `before == manifest == after` candidate fingerprints covering HEAD,
  full index, tracked/untracked content and executable modes, recursive submodules and this
  authority file. Exclude only generated outputs and normally ignored local files, not source
  changes. Input changes invalidate previous evidence and require fresh qualification.

The detailed UCE contract and entrypoints are in [the UCE documentation](../uce/README.md).
No deletion-only index may be committed before the replacement evidence is complete. Local
WIP acceptance, a later commit, remote CI and release publication retain separate identities
and authorization; a single acceptance build does not replace the six-tree release contract.

ABI modes remain mutually exclusive:

- `none` is the default and the only ABI mode used by the QCurl 2.0 release contract.
- `current` and `promotion-candidate` are retained as explicit diagnostic tooling for the future stable ABI project. Their output cannot strengthen, weaken, or block the 2.0 release claim.

The future work required before QCurl can promise binary compatibility is tracked in
`docs/dev/release/stable-abi-contract-and-baseline.md`.

## Candidate qualification and publication conditions

These conditions apply to the actual candidate, not to a historical evidence snapshot.
The original [2026-08-19 observations](../archive/reviews/2026-08-19-qcurl-2.0.0-release-readiness-snapshot.md)
are archived for traceability and do not establish current readiness.

### Local candidate qualification

| ID | requirement | closure condition |
| --- | --- | --- |
| `L1` | Candidate identity | Create an authorized `C1` from the completed remediation, then prove that the superproject and both submodules are clean and that the recorded source identity is `C1`. |
| `L2` | Final qualification | On the clean `C1`, execute the six-tree gate with `--tier full --stage final --abi-mode none`. Every required gate must pass in that fresh run. |
| `L3` | Final evidence integrity | Verify the fresh final manifest against `C1`; reject identity, command, producer-tree, capability, authority, or artifact digest drift; require every registered final gate and artifact to be present and passing. |

### Publication delivery

| ID | requirement | closure condition |
| --- | --- | --- |
| `P1` | Release publication | Only after the local manifest reports `READY_FOR_RELEASE`, freeze the notes, build and verify the release packages and checksums, create the tag, publish the GitHub Release, and verify the uploaded assets against the local digests. |

The following are explicitly **not** QCurl 2.0 release blockers:

- a v2 ABI baseline or `qcurl-core-v2.abi.xml`;
- an ABI compatibility diff;
- ABI baseline promotion; and
- CI/CL execution, which is excluded from this local release-readiness decision.

Passing `L1` through `L3` changes only the local candidate verdict. It does not implicitly close
`P1`, authorize Git operations, or publish the release.

The four-component extraction and its focused package/consumer tests are remediation evidence only.
They do not make the dirty worktree a clean `C1`, replace the six-tree final run, or create the
fresh final manifest required by `L1` through `L3`.

## Final state

The local candidate may enter `READY_FOR_RELEASE` only when the final machine manifest is valid, all required source/package/runtime/symbol gates and artifacts are present, the manifest records `abiMode=none`, and the worktree and submodules are clean. ABI baseline creation and ABI compatibility diff are not part of this decision. The `v2.0.0` tag, remote push, GitHub Release, and asset upload remain outside this contract.
