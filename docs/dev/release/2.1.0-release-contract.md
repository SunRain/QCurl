# QCurl 2.1.0 release contract

## Release identity

- 当前开发候选为 **v2.1.0**；已存在的 `v2.0.0` tag 和 [2.0 历史合同](2.0.0-hard-break-release-contract.md)保持原义。
- `PROJECT_VERSION=2.1.0` 是版本数字的唯一输入；两个运行库均使用 `VERSION 2.1.0`、派生 `SOVERSION 2.1`。
- Core 实体为 `libQCurl.so.2.1.0`，SONAME 为 `libQCurl.so.2.1`；Other Extras 分别为 `libQCurlOtherExtras.so.2.1.0`、`libQCurlOtherExtras.so.2.1`。
- 包配置使用 `SameMinorVersion`；正向 consumer 显式请求最低 `2.1.0`，不使用 `EXACT` 固定整个 patch。
- 从本版本起适用[版本与兼容政策](versioning-and-compatibility.md)：同 `major.minor` 的后续 patch 保护全部已发布 Public 组件，包括 Preview；跨 minor 不保证兼容。这不是 SemVer minor 兼容政策。

本文规定候选必须满足的条件，不证明这些条件已经执行或通过，也不创建 commit、tag、远端 ref 或发布资产。文档校验、配置成功和历史 PASS 均不能建立本候选的发布资格。

## Delivery component model

| 逻辑组件 | 导出 target | 物理交付与消费 |
| --- | --- | --- |
| Core | `QCurl::QCurl` | 默认 Core；shared/static 运行库 |
| Blocking Extras | `QCurl::BlockingExtras` | 显式组件、INTERFACE target；实现随 Core，没有独立 Blocking 库 |
| Other Extras | `QCurl::OtherExtras` | 显式组件、独立 shared/static 运行库；Middleware Extras 为 Stable，Diagnostics/WebSocket 为 Preview |
| Test Support | `QCurl::TestSupport` | 显式组件、开发静态库；不是生产 Runtime |

没有第五组件层。无版本、无组件的 `find_package` 只导入 Core；无过滤安装则安装 producer 构建的全部组件。`Preview` 是成熟度，`Internal` 是可见性，均不增加组件；Preview 公共 API 与其他 Public 安装面享有相同 patch 保护。精确安装面由 [surface manifest](../../../tests/public_api/surface_manifest.json)和[公共头边界](../architecture/public-header-boundary.md)维护。

Core 与 Other Extras 从同一候选组成完整包升级，不承诺任意跨 patch 混装。跨库 private bridge 声明不安装，也不成为公共源码 API；但旧 consumer 已静态链接的 TestSupport 代码通过桥调用新 Core 的运行能力属于同线 patch 验证范围。

## Dependencies and supported ABI tuple

最低依赖为 **Qt 6.10.3、libcurl 8.14.1**；CMake 最低 3.16，C++17。所有组件的构建头、链接库和实际运行库均须满足下限；不以宿主高版本、版本注入或 configure 成功代替真实最低版验收。WebSocket 必须保留默认能力，HTTP/3 仍须实际 QUIC backend 和相应服务端。

首个正式 shared ABI tuple 为：

| 输入 | 支持边界 |
| --- | --- |
| 操作系统 / 架构 | Linux x86_64；精确发行版、GLIBC 版本由真实 final 记录 |
| 编译器 / 标准库 | GCC / libstdc++，C++17，`_GLIBCXX_USE_CXX11_ABI=1`；GCC 最低 11，精确 compiler 与标准库版本由 final 记录 |
| 构建 | Release shared、未插桩、完整组件、默认功能，不裁剪 WebSocket |
| flags / 调试信息 | 实际 flags 随 producer profile 记录；release-shared 保留匹配 DWARF，例如 `-O3 -DNDEBUG -g`；可分离调试文件，但不得用近似构建代替交付库 |
| Qt / libcurl | 最低版独立前缀的真实构建与运行命中；记录精确版本、ABI 和能力 |

后续 patch 的参考比较必须匹配 tuple。架构、标准库 ABI、Qt ABI、模式、功能配置不一致时拒绝比较；不能缩小已支持环境来回避失败。Clang、sanitizer 与 static 仍提供各自产品验证，不因此成为可与 GCC Release 任意互换的二进制配置。static 旧源码重建与 shared 旧二进制运行分开取证。

## Producer tree topology

full 使用五棵物理独立 producer 树；每个 gate 显式绑定对应参数，没有 build-dir 回退或第六棵必需树。

| tree ID | CLI 参数 | 固定能力与职责 |
| --- | --- | --- |
| `release-shared` | `--release-shared-build-dir` | GCC、shared、`BUILD_TESTING=OFF`；完整安装、四组件 consumer、生命周期、动态符号、参考及 ABI |
| `release-static` | `--release-static-build-dir` | GCC、static、`BUILD_TESTING=OFF`；完整安装、四组件 consumer、生命周期 |
| `test-shared-gcc` | `--test-shared-gcc-build-dir` | GCC、shared、`BUILD_TESTING=ON`；QtTest、public-api、libcurl consistency |
| `test-shared-clang` | `--test-shared-clang-build-dir` | Clang、shared、`BUILD_TESTING=ON`；交叉编译器 QtTest/public-api |
| `asan-ubsan-lsan` | `--asan-ubsan-lsan-build-dir` | Clang、shared、`BUILD_TESTING=ON`；ASan/UBSan/LSan 与真实泄漏检测 |

resolved path、compiler family、linkage、测试和 sanitizer capability 必须与职责匹配。缺树、重复物理路径或配置漂移失败。OFF 树不运行 CTest，由 package evidence 直接构建、安装、运行四组件 consumer；`QCURL_BUILD_SHARED_LIBS=OFF` 与 `BUILD_TESTING=ON` 仍在配置时拒绝。

**TSan 在 2.1 为独立非阻断诊断**，不要求第六 producer、插桩 Qt、`package_tsan` 或 `tsan_report` 才能完成 final。未执行结果记为 **NOT_RUN**，环境缺失或失败不变成 PASS，也不计入已通过证据。standalone runner 保留环境检查、实际失败和原始报告；确认的产品缺陷仍须修复。ASan/UBSan/LSan、普通线程/生命周期验证与线程安全合同仍为必需。

## Compatibility evidence

### 首版参考与后续 patch

| 候选 | 必需 ABI 模式 | 条件 |
| --- | --- | --- |
| 新线首版 `M.m.0`，本次 2.1.0 | `snapshot` | 两库 snapshot、完整安装头和 tuple、四组件 consumer 参考、独立必需 round-trip |
| 同线后续 patch `M.m.p`，`p > 0` | `current` | 上述候选参考，加本线首版与最近正式 patch 的两库 ABI、旧源码、旧二进制和行为验证 |

`none` 只用于非 full/final 的局部诊断；full/final 不接受它。patch 不得用 snapshot 绕过比较；首版拒绝伪造的历史输入，也不要求与 2.0 ABI 兼容。

current 必须显式提供 `--abi-reference-first` 和 `--abi-reference-latest`；生成和独立 verify 使用同一输入。first 对应正式 `vM.m.0`，latest 对应已核对同线正式 tag 集中候选之前最高 patch；不能任意挑旧参考。2.1.1 的两项可指向同一 2.1.0 参考，核对身份后去重。参考缺失、损坏、错线、错 tuple、来源不明或以当前候选冒充历史均失败。

首版输出固定在 `release-shared/evidence/compatibility/reference/`，包括 `reference.json`、`validation.json`、`abi/core.snapshot.xml`、`abi/other-extras.snapshot.xml`，以及索引引用的真实库/SONAME 链、TestSupport 静态库、公共及生成头、四组件 consumer 源码和已编译文件、producer profile、符号及运行日志。输出从新的路径开始，不覆盖旧参考。final 引用参考，交付 checksum 再引用 final，避免摘要循环。

捕获后由独立必需 gate `compatibility_reference_roundtrip` 检查同一候选，结果固定在 `evidence/compatibility/roundtrip/report.json` 及其两库 ABI 子报告；`classification=REFERENCE_VALIDATED`、`patchCompatibility=false`。2.1.0 的 round-trip 仅证明首版参考可用，不能写成已经完成真实 2.1.1 升级或 patch 兼容 PASS。每个正式 patch 保留自身参考，累计公共合同与行为回归仍须覆盖两个比较输入之外的既有能力。

### 独立证据与失败语义

- 旧源码通过候选安装前缀重新构建，覆盖四组件、公共头、宏、target 与组件边界。
- 旧二进制检查只运行保存的可执行文件，**不调用 configure/build**。显式使用 candidate release-shared 的 `--build-dir` 核对 profile/tuple 与安装来源；loader 证据须确认 QCurl 两库来自候选完整前缀，拒绝 ambient `LD_PRELOAD`、旧 RPATH 或宿主库偷渡。
- 两库分别显式使用参考/候选真实 ELF 和旧/新公共头做完整 ABI 分析，再用 `--no-added-syms` 做保守残余比较，残余必须退出 0。两侧 snapshot 仍须归档、验证语义及与真实库对应；XML 比较曾在真实 class-only 方法/虚表负向控制中漏报，不能独立承担兼容判定。真实 ELF 是固定比较路线，不是自动 fallback。工具错误、已识别破坏、未知位和残余 4 均失败；不能把原始返回码 4 一概解释成兼容。
- 真实微型 ELF 负向控制区分纯新增、删除、同名导出布局/返回类型变化；mock 或只看符号名不能替代它。
- public 行为回归、旧源码、旧二进制、ABI 和动态符号 hygiene 是不同证据，不能互相替代。跨线隔离用例须明确因旧 SONAME 缺失失败，崩溃或其他依赖缺失不算通过。

历史比较结果固定为 `evidence/compatibility/check-first/report.json` 和 `check-latest/report.json` 及其 ABI 子报告；旧源码重建另写 `source-first/report.json` / `source-latest/report.json`。正式 patch 的 check 与 rebuild-source 均强制 `--require-history`，拒绝将同候选 round-trip 充作历史升级；重合历史输入按已核对身份去重。实现复用现有 GateStep、artifact contract、候选身份和摘要验证，不设人工兼容 PASS、受控 v2 baseline 更新或 promotion 发布入口。

## Version-controlled authority and CI inputs

唯一 release identity authority 是本文件：
`docs/dev/release/2.1.0-release-contract.md`。full 必须且只能提供
`--authority docs/dev/release/2.1.0-release-contract.md`；缺失、重复、额外 authority 或旧 2.0 authority 均拒绝。UCE 使用同一默认输入。[长期政策](versioning-and-compatibility.md)是受版本控制的规范源码，不增加第二个 authority 参数。

策略字典仍位于 `docs/dev/uce/policy_violations_dictionary.json` 和对应 Markdown，代码集合须一致，未注册 code 或缺文件失败。`.helloagents/` 是本地忽略目录，不是 release authority、CI 输入或候选身份；发布门禁不能依赖本地方案。受控历史文档保留追溯意义，不能作为当前 authority。

UCE nightly 承接完整 acceptance：保留 master/main/develop push、manual dispatch、适用 path filters、recursive checkout、依赖、configure/build、基础设施测试、public-api-slow、capability `skip=fail`、本地 httpbin 的 strict offline/env 与 libcurl consistency p0。空选集、列举失败、非零命令、workload/finalization 或归档异常失败，保留注册 policy code 和可用诊断。

必需归档为 `<run-id>/manifest.json`、`policy_violations.json`、`<run-id>.tar.gz` 和 `<run-id>.archive-envelope.json`；独立验证内部/外部元数据、成员、完整 gzip 与 envelope digest/size。fresh nightly 的 before、manifest、after 必须绑定同一 HEAD、index、tracked/untracked 内容和执行模式、递归子模块及本 authority。输入改变即失效，归档失败不是成功。详见 [UCE](../uce/README.md)。

## Candidate qualification and publication conditions

| 阶段 | 必须取得的证据 |
| --- | --- |
| remediation | 完成本线政策、实现和失败控制；dirty 结果只证明对应局部状态 |
| clean C1 | 经授权形成唯一候选；工作树与递归子模块干净，冻结源码/依赖/文档/机器输入 |
| fresh full/final | 全新五树、2.1 authority、本次 snapshot；当前注册 required gate/artifact 全部存在且真实通过 |
| independent verify | 用同一参数重新核对候选、authority、命令、producer capability、参考来源/tuple、引用的真实文件及摘要；`result=pass`、`valid=true`、`reasons=[]` |
| 本地交付 | 同一候选的真实 TGZ、源码、Arch、API 文档与 compatibility-reference，逐项验内容、解包 consumer 和 checksum |
| 远端发布 | 独立授权后创建/推送 tag、Release、上传并下载回验实际资产 |

full 仍须完整 GCC/Clang CTest、public-api、公用能力、shared/static 安装与四组件 consumer/生命周期、libcurl consistency all+ext、动态符号、ASan/UBSan/LSan、UCE nightly、Doxygen 与 metadata。不得照搬历史测试总数；检查实际注册集合、skip、disabled、退出码与原始失败。

READY 只能由当前 clean C1 的有效 full/final 和独立 verifier 推导，不新增可人工填写的 READY 字段。只改归档字节可复验包/checksum；源码、依赖或构建输入改变要求新候选与 fresh qualification。最低依赖未被真实验证时，不能宣称完整资格通过。

本文未记录任何产品 PASS。提交、tag、push、Release、资产上传和下载回验各有授权边界；本地资格不表示远端已发布。具体命令见[发布操作](release-procedure.md)，用户升级见[迁移到 2.1](../../user/migration-2.1.md)。
