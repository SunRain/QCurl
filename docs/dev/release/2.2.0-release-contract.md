# QCurl 2.2.0 release contract

## Release identity

- 当前开发候选为 **2.2.0**，是 2.2 兼容线首版。既有 `v2.1.0` / `v2.1.1` tag 保留原义；[2.1 历史合同](2.1.1-release-contract.md)不再作为当前 authority。
- `PROJECT_VERSION=2.2.0` 是构建版本数字的唯一输入；两个运行库使用 `VERSION 2.2.0`、派生 `SOVERSION 2.2`。Arch `pkgver` 与项目版本强制一致。
- Core 实体为 `libQCurl.so.2.2.0`，SONAME 为 `libQCurl.so.2.2`；Other Extras 分别为 `libQCurlOtherExtras.so.2.2.0`、`libQCurlOtherExtras.so.2.2`。不生成 `.so.2.1` 或 `.so.2` 兼容链接。
- 包配置使用 `SameMinorVersion`；当前 consumer 请求最低 `2.2.0`。2.1.x 请求不得被 2.2 包满足；跨线下游须重建，不能靠替换链接绕过边界。
- 延续[版本与兼容政策](versioning-and-compatibility.md)：同 `major.minor` 后续 patch 保护全部已发布 Public 组件，包括 Preview；跨 minor 不保证源码、ABI、安装消费或行为兼容。这不是 SemVer minor 兼容政策。

本版本收拢共同请求策略、传输/Share/TLS 生命周期调整与接收空闲超时；可观察默认值和失败语义变化见 [CHANGELOG](../../../CHANGELOG.md#current-release)及[迁移到 2.2](../../user/migration-2.2.md)。这些变化按新线交付，不宣称与 2.1 patch 兼容。

本文规定候选必须满足的条件，不证明条件已经通过，也不创建 commit、tag、远端 Release 或资产。文档校验、配置成功、局部回归和旧候选结果均不能建立本候选的发布资格。

## Delivery component model

| 逻辑组件 | 导出 target | 物理交付与消费 |
| --- | --- | --- |
| Core | `QCurl::QCurl` | 默认 Core；shared/static 运行库 |
| Blocking Extras | `QCurl::BlockingExtras` | 显式组件、INTERFACE target；实现随 Core，没有独立 Blocking 运行库 |
| Other Extras | `QCurl::OtherExtras` | 显式组件、独立 shared/static 运行库；Middleware Extras 为 Stable，Diagnostics/WebSocket 为 Preview |
| Test Support | `QCurl::TestSupport` | 显式组件、开发静态库，不是生产 Runtime |

无版本、无组件的 `find_package` 只导入 Core；无过滤安装部署 producer 构建的完整包。精确 Public 安装面由 [surface manifest](../../../tests/public_api/surface_manifest.json)枚举，检查见[公共头边界](../architecture/public-header-boundary.md)。Preview 只表达成熟度，不豁免同线 patch 兼容。

Core、Other Extras 与 TestSupport 来自同一候选；不承诺跨线或任意跨 patch 混装。private bridge 不安装、不成为公共源码 API；但 2.2 后续 patch 必须验证旧 consumer 已静态链接的 TestSupport 与新 Core 的桥接仍可运行。

## Dependencies and supported ABI tuple

最低依赖保持 **Qt 6.10.3、libcurl 8.14.1、CMake 3.16、C++17**。构建头、链接库和实际运行库均须满足下限；不能以宿主高版本或版本注入代替真实最低版验收。正式完整包保留 WebSocket，HTTP/3 须验证实际 QUIC backend 和服务端。

正式 shared 二进制支持范围为 **Linux x86_64、GCC/libstdc++、C++17、`_GLIBCXX_USE_CXX11_ABI=1`、Release、未插桩、完整组件与默认功能**；GCC 最低 11。真实 final 记录 OS/GLIBC、compiler/标准库、Qt/libcurl 编译和运行版本、路径、配置与 flags。release-shared 保留与交付库对应的 DWARF，例如 `-O3 -DNDEBUG -g`。

后续 patch 必须匹配参考 tuple；不同架构、标准库 ABI、Qt ABI、模式或功能配置不能冒充兼容证明。Clang、static 与 sanitizer 承担各自验证职责，不承诺与 GCC Release 任意二进制互换。static 旧源码重建和 shared 旧二进制运行分别取证。

## Producer tree topology

full 使用五棵物理独立 producer 树，每个 gate 显式绑定参数；不复用旧候选输出或用符号链接合并路径。

| tree ID | CLI 参数 | 能力与职责 |
| --- | --- | --- |
| `release-shared` | `--release-shared-build-dir` | GCC、Release shared、`BUILD_TESTING=OFF`；完整安装/四组件 consumer/生命周期、符号、参考及 ABI |
| `release-static` | `--release-static-build-dir` | GCC、Release static、`BUILD_TESTING=OFF`；完整安装/四组件 consumer/生命周期 |
| `test-shared-gcc` | `--test-shared-gcc-build-dir` | GCC shared、`BUILD_TESTING=ON`；QtTest/public-api/libcurl consistency |
| `test-shared-clang` | `--test-shared-clang-build-dir` | Clang shared、`BUILD_TESTING=ON`；交叉编译器 QtTest/public-api |
| `asan-ubsan-lsan` | `--asan-ubsan-lsan-build-dir` | Clang shared、`BUILD_TESTING=ON`；ASan/UBSan/LSan 与真实泄漏检测 |

缺树、重复物理路径或 capability 漂移失败。两棵 OFF 树验证真实最低版 Qt/libcurl 与安装 consumer；ON 树使用固定 bundled curl，逐树记录实际 provider，不能把它宣称为最低 libcurl。OFF 树不运行 CTest；static + `BUILD_TESTING=ON` 仍以 `QCURL_STATIC_TESTING_UNSUPPORTED` 拒绝。

**TSan 在 2.2 继续作为独立非阻断诊断**，未运行记 NOT_RUN，环境缺失或失败不得计为 PASS。确认的产品缺陷仍须处理；ASan/UBSan/LSan、普通线程与生命周期验证仍为必需。命令和环境见 [UCE](../uce/README.md)。

## Compatibility evidence

### 本次首版：snapshot

2.2.0 的 full/final 必须使用 `--abi-mode snapshot`，不提供 `--abi-reference-first` 或 `--abi-reference-latest`。拒绝 `current`、历史参考参数和 `none` 绕过；不要求与 2.1 ABI 兼容，也不把 2.1 参考重命名为 2.2 参考。

`compatibility_reference_capture` 从当前 release-shared 的真实完整安装捕获 `evidence/compatibility/reference/`：包括 `reference.json`、`validation.json`、两库 snapshot/真实库及 SONAME 链、TestSupport 静态库、全部 Public 头、tuple/profile、四组件源码与仅构建一次的可执行文件、原始日志和来源 commit/submodule。新目录不覆盖旧参考；保留匹配调试信息。

独立必需 gate `compatibility_reference_roundtrip` 输出 `evidence/compatibility/roundtrip/report.json` 和两库 ABI 子报告。成功分类为 `REFERENCE_VALIDATED`、`patchCompatibility=false`，只证明本候选参考可用，不是一次真实 patch 升级兼容 PASS。

### 后续 2.2 patch：current

后续 `2.2.p`（p > 0）使用 `current`，显式提供正式 `v2.2.0` 首版参考与候选之前最近正式 2.2 patch 参考。核对 tag/commit、资产与 tuple 后，相同输入去重。缺失、损坏、错线、错 tuple、来源不明或当前候选冒充历史均失败；不能用 snapshot 跳过历史比较。

旧源码、两库 ABI、旧二进制和公开行为分别取证。历史 check/rebuild-source 强制 `--require-history`；旧二进制运行不 configure/build，loader 记录须确认两库来自候选 stage，拒绝旧 RPATH、宿主库或 ambient `LD_PRELOAD` 偷渡。结果路径为 `check-first` / `check-latest` 与独立 `source-first` / `source-latest`。

两库完整和残余 ABI 比较始终输入旧/新真实 ELF 及公共头；snapshot 继续归档和校验对应性，不能仅比较 XML。残余比较必须退出 0，工具错误、已识别破坏或未知返回位均失败，原始返回码 4 不能一概当作兼容。真实微型 ELF 正负控制、动态符号 hygiene 与产品 consumer 各有职责，不能相互替代，见 [ABI 操作](stable-abi-contract-and-baseline.md)。

## Version-controlled authority and CI inputs

唯一当前 release identity authority 为 `docs/dev/release/2.2.0-release-contract.md`。full 必须且只能提供 `--authority docs/dev/release/2.2.0-release-contract.md`；缺失、重复、额外或旧 2.1/2.0 authority 均拒绝。UCE 使用同一默认输入；长期版本政策不增加第二个 authority 参数。

`.helloagents/` 是本地忽略知识库，不是 CI 输入或发布身份。策略字典仍为 `docs/dev/uce/policy_violations_dictionary.json` 及对应 Markdown；未注册 code、缺文件或代码集合不一致失败。

UCE nightly 保留 push/manual acceptance、recursive checkout、依赖/configure/build、基础设施、public-api-slow、capability `skip=fail`、本地 httpbin strict offline/env 和 libcurl consistency p0。空集合、命令非零、workload/finalization 或归档异常均失败。必需 `<run-id>/manifest.json`、`policy_violations.json`、tar.gz 和 archive-envelope，独立验证成员、字节和完整 gzip。执行前/manifest/执行后必须绑定同一 HEAD、index、内容、执行模式、递归子模块及本 authority；漂移使证据失效。操作见 [UCE](../uce/README.md)。

## Candidate qualification and publication conditions

| 阶段 | 必需结果 |
| --- | --- |
| remediation | 完成本版本实现与发布输入及失败控制；dirty 结果只证明对应工作区状态 |
| clean C1 | 唯一候选提交及递归子模块干净，冻结源码、依赖、文档与构建输入 |
| fresh full/final | 全新五树、本 authority、snapshot；当前注册 required gate/artifact 齐全且真实通过 |
| independent verify | 同参数重算候选、authority、命令、capability、参考与实际文件摘要；`result=pass`、`valid=true`、`reasons=[]` |
| 本地交付 | 同一候选的真实 TGZ、源码、Arch、API 文档、compatibility-reference；内容检查、解包 consumer 与 checksum |
| 远端发布 | 授权后创建/推送 tag、Release，上传并下载回验实际资产 |

full 仍要求完整 GCC/Clang CTest、public-api、shared/static 四组件安装消费与生命周期、libcurl consistency all+ext、动态符号、能力检查、ASan/UBSan/LSan、UCE nightly、Doxygen 与 metadata。检查实际注册集合、skip、disabled、退出码和原始失败；局部通过不代替完整验收。

READY 只能由有效 full/final 和独立 verifier 推导，不另建人工 READY 字段。源码、依赖或构建输入变化要求新候选与 fresh qualification；仅归档字节变化则复验包和 checksum。最低依赖未实测不能宣称完整资格通过。本地就绪不表示远端已发布，具体执行见[发布操作](release-procedure.md)。
