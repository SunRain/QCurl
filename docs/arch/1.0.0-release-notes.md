# QCurl 1.0.0 release notes

本文是最终 GitHub Release 的候选说明草稿；在 tag 与 GitHub Release 实际创建前，不表示远程 release 已完成。

当前候选仍需完成本文末尾的最终验证；在这些门禁生成最后一次源码变更之后的通过证据前，不表示当前 checkout 已达到 Core Stable 或 release-ready。

`QCurl 1.0.0` 是项目首个 stable line。它稳定默认 Core install surface，同时保留 Blocking Extras、Test Support 和 Other Extras 的显式 opt-in 边界。

## Stable scope

Core / Stable 覆盖默认 `find_package(QCurl)` / `QCurl::QCurl` consumer contract：

- 异步 HTTP Core API：`QCNetworkAccessManager`、`QCNetworkRequest`、`QCNetworkReply`。
- 请求配置：TLS、proxy、timeout、redirect、transfer、retry、cache policy；Core 入口只接受 HTTP/HTTPS，重试默认关闭并对非幂等 method 使用统一幂等键门禁。
- 显式启用的结构化缓存：按 method、规范化 URL、Vary 请求头和 `cachePartitionKey` 隔离认证上下文，当前稳定存储范围为 GET 200。
- Proxy 默认 fail-closed：未显式配置代理或设置 `ProxyType::None` 时，不继承 libcurl 的 `HTTP_PROXY` / `HTTPS_PROXY` 环境代理。
- HTTP method / version / error / priority types。
- lane-aware scheduler。
- Cache lookup、Multipart/body helper、transfer jobs。
- logger、default logger、cancel token、middleware base。
- connection pool config / manager。
- Core cookie API 使用 `QCurl::QCCookie`、`QCCookieOperationResult` 与
  `QCCookieExportResult`；默认 Core consumer 不需要 QtNetwork cookie 类型或
  `Qt6Network` 链接依赖。

## Package-shipped non-default surfaces

- Blocking Extras：同步 value-result client、受限内存 body、download-to-device 和 blocking cookie store。
- Test Support / Explicit opt-in：mock/capture/test-support helper，仅测试 opt-in。
- Other Extras / Preview：Diagnostics、Middleware Extras、WebSocket；WebSocket 保持非阻塞 Preview 且不提供手工 `permessage-deflate`，它们可随包发布，但不属于 1.0.0 Core Stable 承诺。

## Compatibility policy

1.0.0 是 QCurl 首个 Stable ABI baseline。旧历史版本和 RC 叙事保留为内部参考，不进入当前 release history 主线；本发布不提供旧 `2.x` / `3.x` 兼容层。

Core cookie public API 是 1.0.0 Core surface 的一部分。旧 QtNetwork cookie
类型不会作为 overload、alias、shim 或 wrapper 保留。下游应迁移到
`QCurl::QCCookie` 并按当前 `QCurl::QCurl` / `QCurl::OtherExtras` target 边界重新构建。

未显式配置代理的请求不再继承 libcurl 环境代理。需要代理的调用方必须通过
`QCNetworkProxyConfig` 显式设置代理类型、地址、端口和认证信息。

`QCNetworkRequest(const QUrl &)` 使用 `explicit`，不再允许 `QUrl` 隐式转换为
`QCNetworkRequest`。原调用 `sendRequest(url)` 必须迁移为
`sendRequest(QCNetworkRequest{url})`。该源码不兼容变更不改变构造函数符号或对象布局，
不提供兼容重载、弃用入口或迁移开关。

`QCNetworkReply` 不再重复声明或转发 `QObject::deleteLater()`。调用方仍使用原有
`reply->deleteLater()` 源码形式，调用的是继承的 QObject slot；1.0 Core 导出面和派生
meta-object 不包含 `QCNetworkReply::deleteLater()` wrapper。ABI hard-break 报告必须记录
旧派生符号的删除，不能通过 alias、shim 或刷新旧 baseline 隐藏该差异。
