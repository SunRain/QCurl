# QCurl 2.0.0 hard-break release contract

## Release identity

- Latest published release: `v1.0.0`.
- Current development candidate: `v2.0.0`.
- This document defines the local release-candidate contract. It does not create a tag, push a ref, or publish an asset.
- `PROJECT_VERSION` is `2.0.0`; the `QCurl` and `QCurlOtherExtras` shared libraries use `VERSION 2.0.0` and `SOVERSION 2`.
- The Core shared artifact is `libQCurl.so.2.0.0`.

The release identity has one ordered route:

1. `R=0d1e57dcd68edcca9c7dcac28841571a8a6e00ad` is the read-only review baseline.
2. `remediation` is the uncommitted implementation and pre-commit verification stage. It is not a release candidate.
3. `C1` is the clean implementation and promotion candidate. It does not modify the controlled v2 ABI baseline.
4. `promotion` verifies and copies the manifest-bound ABI snapshot without regenerating ABI evidence.
5. `C2` is the baseline-only direct child of `C1` and is the sole final candidate.
6. `final` runs fresh qualification against clean `C2`; no evidence from `R`, remediation, or `C1` can replace it.

Until this route reaches a passing `final` manifest bound to `C2`, the release state is
`REMEDIATION_REQUIRED / NOT_READY_FOR_RELEASE`.

## Producer tree topology

`full` release evidence uses six physically distinct build trees. Every gate step receives
the producer path through one of these explicit options; no step may substitute another tree:

| tree ID | CLI option | fixed capability | producer responsibility |
| --- | --- | --- | --- |
| `release-shared` | `--release-shared-build-dir` | `BUILD_TESTING=OFF`, `QCURL_BUILD_SHARED_LIBS=ON` | shared install/export/consumer/lifecycle, symbols and ABI |
| `release-static` | `--release-static-build-dir` | `BUILD_TESTING=OFF`, `QCURL_BUILD_SHARED_LIBS=OFF` | static install/export/consumer/lifecycle |
| `test-shared-gcc` | `--test-shared-gcc-build-dir` | `BUILD_TESTING=ON`, GCC | GCC QtTest, public API and libcurl consistency |
| `test-shared-clang` | `--test-shared-clang-build-dir` | `BUILD_TESTING=ON`, Clang | Clang QtTest and public API cross-check |
| `asan-ubsan-lsan` | `--asan-ubsan-lsan-build-dir` | `BUILD_TESTING=ON`, Clang, ASan/UBSan/LSan | sanitizer evidence |
| `tsan` | `--tsan-build-dir` | `BUILD_TESTING=ON`, Clang, TSan | thread-sanitizer evidence |

The gate rechecks each tree's resolved path, compiler family, `BUILD_TESTING`,
`QCURL_BUILD_SHARED_LIBS` and sanitizer capability before running a step. Missing paths,
duplicate physical paths or capability drift fail closed. The OFF trees do not register CTest;
`scripts/release_package_evidence.py` builds, installs and runs the four installed-package
consumers and lifecycle report directly from the corresponding OFF tree.

## Hard-break boundary

The v1 to v2 transition may remove public APIs and ABI symbols named by the active plan. It does not relax memory safety, thread ownership, protocol semantics, error propagation, local-fixture requirements, or release evidence.

The cache policy contract has one route: ordered `QList<QCNetworkCacheMetadata::RawHeaderPair>` input. The three lossy `QMap<QByteArray, QByteArray>` policy overloads and their conversion helper are absent. Header observation and storage APIs remain separate from policy evaluation.

`QCWebSocketPool` remains owner-thread-only, asynchronous, mutex-free, and free of nested event loops. Its four public signals must support synchronous direct-slot reentry for `acquire`, `release`, and `clearPool`. Keepalive evidence covers matching Pong, delayed Pong, wrong nonce, no Pong, and disconnect-after-Ping using the local evidence server.

The acquire result and synchronous lease operations have one pure-value contract:

```cpp
using LeaseId = QCWebSocketAcquireResult::LeaseId;
[[nodiscard]] LeaseResult resolveLease(LeaseId leaseId, QCWebSocket **socket) const;
[[nodiscard]] LeaseResult release(LeaseId leaseId);
[[nodiscard]] bool clearPool(const QUrl &url = QUrl(), QString *error = nullptr);
[[nodiscard]] bool setConfig(const QCWebSocketPoolConfig &config, QString *error = nullptr);
```

`QCWebSocketAcquireResult` carries only status, diagnostics, and an opaque nonzero lease ID. It
does not carry a socket pointer. `resolveLease()` and `release()` must be called on the pool owner
thread while the pool is not `Destroying`; they report wrong-thread, destroyed-pool, invalid,
unknown, and inactive-lease failures through `LeaseResult` without changing pool state. A resolved
socket is a non-owning borrow valid only while the same lease remains active. `clearPool()` and
`setConfig()` return `false` with a stable diagnostic and no state change for rejected calls;
successful calls return `true` and clear the optional error output. No queued or cross-thread
mutator route is provided. `preWarm()` reports a failed synchronous lease release as one
`ConnectionFailed` result and does not increase the warmed count.

Static testing is unsupported. `QCURL_BUILD_SHARED_LIBS=OFF` together with `BUILD_TESTING=ON`
must fail during configure with the fixed diagnostic
`QCURL_STATIC_TESTING_UNSUPPORTED：静态构建不支持测试`; only the negative configure test
covers that rejected combination.

## Release evidence

The candidate gate compares the immutable v1 historical baseline with the v2 candidate and records a hard-break report. The final gate compares the candidate with the promoted v2 baseline and requires zero removed, changed, or added ABI entries.

For a `promotion-candidate` manifest, the required artifact records use these
stable identifiers: `candidate_core_library`, `v1_baseline`,
`abi_hardbreak_current_snapshot`, and `abi_hardbreak_report`. Each record
contains the normalized path and the SHA-256 digest of the regular file. The
manifest also records its own normalized path under `promotion.manifest_path`;
the manifest file itself is verified only through `manifestPayloadSha256`.

The only release identity authority inputs are exactly:

1. `.helloagents/plans/202608051224_qcurl_v2_comprehensive_review_remediation/requirements.md`.
2. `.helloagents/plans/202608051224_qcurl_v2_comprehensive_review_remediation/plan.md`.
3. `.helloagents/plans/202608051224_qcurl_v2_comprehensive_review_remediation/contract.json`.
4. This release contract.

Task progress, session state, finding maps, QA output, closeout output, and historical reviews are derived runtime data. They do not alter the authority digest.

ABI gate modes are mutually exclusive:

- `current` requires `abi_current_baseline_diff` against `qcurl-core-v2.abi.xml`.
- `promotion-candidate` requires `abi_hardbreak_report` against `qcurl-core-v1.abi.xml` and does not run the current-baseline diff.

Promotion may write only `abi/baseline/qcurl-core-v2.abi.xml`, and only after clean
`C1`, a passing promotion manifest, a clean submodule state, Linux, and the complete
toolchain have been revalidated. Promotion is copy-only: it must not call `abidw` or
`abidiff`, and it must not rewrite the verified snapshot, hard-break report, or symbol
report. The v1 baseline remains unchanged.

## Final state

The local candidate may enter `READY_FOR_RELEASE` only when the final machine manifest is valid, all required gates and artifacts are present, the final v2 ABI diff is empty, and the worktree and submodules are clean. The `v2.0.0` tag, remote push, GitHub Release, and asset upload remain outside this contract.
