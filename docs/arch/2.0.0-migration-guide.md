# Migrating from QCurl 1.0.0 to 2.0.0

QCurl 1.0.0 remains the published historical release. QCurl 2.0.0 is a deliberate hard-break candidate; downstream code must be rebuilt against the v2 headers and libraries.

## Cache policy APIs

Remove calls to these v1 overloads:

- `parseExpirationDate(const QMap<QByteArray, QByteArray> &)`
- `isCacheable(const QMap<QByteArray, QByteArray> &)`
- `varyHeaderNames(const QMap<QByteArray, QByteArray> &)`

Pass ordered `QList<QCNetworkCacheMetadata::RawHeaderPair>` values instead. Preserve response-header order and duplicate fields when constructing the raw-header list. `headers()` and `setHeaders()` remain observation and storage APIs; they are not alternate policy routes.

## Linking and ABI

Update package and deployment expectations from `SOVERSION 1` to `SOVERSION 2`. The Core shared library is `libQCurl.so.2.0.0`, and the v2 ABI baseline is `abi/baseline/qcurl-core-v2.abi.xml` after controlled promotion.

Do not copy the v1 baseline into the v2 location or use a compatibility wrapper. The candidate gate uses `qcurl-core-v1.abi.xml` only for the intentional hard-break report; the final gate uses the promoted v2 baseline for a zero-change diff.

## Release workflow

Use the v2 release contract, the promotion-candidate ABI mode, and the current ABI mode in their defined order. A local readiness result does not create a tag or remote release.
